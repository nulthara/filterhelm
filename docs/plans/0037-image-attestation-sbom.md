## Problem

The GHCR image has no provenance and no software bill of materials. A user who pulls
`ghcr.io/nulthara/filterhelm` cannot check that this repository's workflow built the image,
or see what is inside it without unpacking it. Plan 0034 deferred both items because
GitHub artifact attestations are free only for public repositories. The repository went
public on 2026-10-17, so signed attestations are now available.

## Scope

In:
- A signed SLSA build provenance attestation for every published image, pushed to GHCR
- An SPDX SBOM generated by Syft, signed as an SBOM attestation, and pushed to GHCR
- The job permissions those steps need
- Adding `ghcr.io` and `spdx.dev` to the hygiene allow-list, so the docs can show the
  `oci://` verify commands
- Updated workflow tests
- Verify instructions in `README.md` and `docs/deploy.md`
- Bumping the version to 0.2.1, so the first attested release can be tagged right after
  merge

Out:
- Attesting `v0.2.0`. That image already shipped without attestations, and re-tagging it
  would overwrite a published tag.
- BuildKit's own `provenance` and `sbom` outputs. They stay `false`. GitHub's signed
  attestations replace them, and two unsigned BuildKit attestation manifests would
  only confuse verification.
- Per-architecture SBOMs (see Approach)
- Verifying attestations at deploy time. The forge deploy still builds locally.
- GitHub Releases, vulnerability scanning, and a dependency snapshot upload

## Approach

**One action for both attestations.** `actions/attest` v4 creates the provenance
attestation by default, and an SBOM attestation when it receives `sbom-path`. As of v4,
`actions/attest-build-provenance` and `actions/attest-sbom` are thin wrappers around it,
and `attest-sbom` is deprecated. Both steps attest the image by
`subject-name: ${{ env.IMAGE }}` (no tag) and
`subject-digest: ${{ steps.build.outputs.digest }}`, with `push-to-registry: true`.
GitHub stores the signed bundles, and GHCR receives them as OCI referrers.

**The multi-arch digest.** `build-push-action` outputs the digest of the image index,
the manifest list that covers `amd64` and `arm64`. Both attestations bind to that
digest. `gh attestation verify oci://ghcr.io/nulthara/filterhelm:X.Y.Z` resolves the tag
to that same index digest, so the verify commands work on the tag users actually pull.

**SBOM.** `anchore/sbom-action` runs Syft against
`${{ env.IMAGE }}@${{ steps.build.outputs.digest }}` and writes SPDX JSON. Syft scans the
runner's platform, `linux/amd64`. The `arm64` image installs the same pinned packages
from `requirements.lock` on the same digest-pinned base image, so the package list
matches apart from per-architecture wheel files. The docs say the SBOM describes the
`amd64` image.

Rejected alternative: one SBOM per architecture, each attested against its platform
manifest digest. That needs a step to parse `docker buildx imagetools inspect` output,
and `gh attestation verify` on the tag would no longer find the SBOM, because the tag
resolves to the index, not to a platform manifest.

The action installs Syft at run time. v0.24.3 pins Syft v1.54.0 by default and pins the
installer to that tag. The workflow still sets `syft-version: v1.54.0` explicitly, so a
test can assert it and a future action bump cannot silently move it. The action passes
`registry-username` and `registry-password` from `github.actor` and `GITHUB_TOKEN`,
because the package can be private even when the repository is public. It sets
`upload-artifact: false` and `upload-release-assets: false`, so the action needs no
extra permissions. The SBOM's home is the attestation.

**Permissions.** The job adds `id-token: write` (OIDC for the Sigstore certificate),
`attestations: write` (storing the attestation), and `artifact-metadata: write`. That
last one is for the storage record `actions/attest` creates by default with
`push-to-registry` on an organization-owned repository. `packages: write` already covers
the registry push.

**Pinned versions.** These were checked on 2026-10-17. Each release was public for more
than 24 hours:

| Action / tool | Version | Commit SHA | Released |
| --- | --- | --- | --- |
| `actions/attest` | v4.2.2 | `1e69f48acb82d1966a394da916b4c1698aa569d6` | 2026-08-04 |
| `anchore/sbom-action` | v0.24.3 | `66cbf4bc1f1c0d2edc94016e65bc221b6bb0ad6c` | 2026-10-02 |
| Syft (installed by the action) | v1.54.0 | — | 2026-10-01 |

`anchore/sbom-action` v0.24.3 is an annotated tag. The SHA above is the commit it points
to (`^{}`), not the tag object. Use these SHAs verbatim. The implementer has no network.

**Hygiene allow-list.** `tests/test_repo_hygiene.py` flags any URL host that is not on
`ALLOWED_DOMAINS`. The verify commands need `oci://ghcr.io/...` and the SPDX predicate URI
`https://spdx.dev/...`, so both domains join the list. Both are public, generic hosts,
not private infrastructure.

## Steps

1. **Workflow.** In `.github/workflows/publish-image.yml`:
   - Set `jobs.publish.permissions` to exactly:

     ```yaml
     permissions:
       contents: read
       packages: write
       id-token: write
       attestations: write
       artifact-metadata: write
     ```

   - Add `id: build` to the "Build and push" step. Leave its `with:` block unchanged,
     including `provenance: false` and `sbom: false`.
   - After "Build and push", append these three steps in this order:

     ```yaml
     - name: Generate SBOM
       uses: anchore/sbom-action@66cbf4bc1f1c0d2edc94016e65bc221b6bb0ad6c # v0.24.3
       with:
         image: ${{ env.IMAGE }}@${{ steps.build.outputs.digest }}
         registry-username: ${{ github.actor }}
         registry-password: ${{ secrets.GITHUB_TOKEN }}
         format: spdx-json
         output-file: sbom.spdx.json
         syft-version: v1.54.0
         upload-artifact: false
         upload-release-assets: false
     - name: Attest build provenance
       uses: actions/attest@1e69f48acb82d1966a394da916b4c1698aa569d6 # v4.2.2
       with:
         subject-name: ${{ env.IMAGE }}
         subject-digest: ${{ steps.build.outputs.digest }}
         push-to-registry: true
     - name: Attest SBOM
       uses: actions/attest@1e69f48acb82d1966a394da916b4c1698aa569d6 # v4.2.2
       with:
         subject-name: ${{ env.IMAGE }}
         subject-digest: ${{ steps.build.outputs.digest }}
         sbom-path: sbom.spdx.json
         push-to-registry: true
     ```

2. **Workflow test.** In `tests/test_supply_chain.py`, update `test_publish_workflow_shape`.
   Keep every existing assertion except the permissions one, and change that to the new
   five-key mapping. Add the assertions listed in Tests.
   `test_publish_workflow_pins_actions_by_sha` needs no change, because it already covers
   the new `uses:` lines.

3. **Hygiene allow-list.** In `tests/test_repo_hygiene.py`, add `"ghcr.io"` and
   `"spdx.dev"` to `ALLOWED_DOMAINS`. Change nothing else in that file.

4. **Docs.**
   - `README.md`: in "Run the published image", after the line "Pin a version tag such as
     `0.2.0` instead of `latest` for anything long-lived.", add a short paragraph. Say that each release image carries signed
     build provenance and an SPDX SBOM, which describes the `amd64` image. Show:

     ```bash
     gh attestation verify oci://ghcr.io/nulthara/filterhelm:X.Y.Z --owner nulthara
     gh attestation verify oci://ghcr.io/nulthara/filterhelm:X.Y.Z --owner nulthara \
       --predicate-type https://spdx.dev/Document/v2.3
     ```

   - `docs/deploy.md` "Releasing": after the paragraph about the image tags, add one
     paragraph saying the workflow signs provenance and an SBOM, then pushes both to GHCR.
     Show the same two commands as the release check.

5. **Version bump.** Set `__version__ = "0.2.1"` in `app/__init__.py`, set
   `"version": "0.2.1"` in `frontend/package.json`, and set the top-level `version` and
   `packages[""].version` in `frontend/package-lock.json` to `"0.2.1"`. Edit the lock by
   hand, because `npm install` needs network. No frontend source changes, so
   `app/static/ui/` must not change. The header reads the version from `/api/version`.
