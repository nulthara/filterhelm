## Problem

FilterHelm ships as 0.2.1. The pre-public feature list closed on 2026-10-17, and the app
now has a public docs site, a signed GHCR image, and first-instance onboarding. The version
should say the project is stable. Under 1.x, a major-only image tag (`1`) also becomes
useful, because users can follow every non-breaking release without pinning a patch.

## Scope

In:
- Bump the app version from `0.2.1` to `1.0.0` in every field `test_versions_agree` checks.
- Publish a major-only image tag (`1`) alongside `X.Y.Z`, `X.Y` and `latest`.
- Update docs and the bug-report placeholder that quote a concrete version or list image tags.

Out:
- A CHANGELOG or release-notes file. The GitHub release text stays a manual step.
- Tagging `v1.0.0` and pushing to the GitHub mirror. Those happen after merge, by hand,
  per `docs/deploy.md` § Releasing.
- Any frontend source change or rebuild of `app/static/ui/`.
- Dependency bumps.
- Plan files under `docs/plans/` that quote old versions. They are history.

## Approach

Follow the existing release procedure in `docs/deploy.md` § Releasing, which says to bump
`app/__init__.py`, `frontend/package.json`, and both root version fields in
`frontend/package-lock.json` through a plan. `pyproject.toml` reads the version from
`app.__version__`, so it needs no edit.

Edit the lockfile's two root `"version"` fields by hand. Do not run `npm install` or
`npm version`, because either can touch resolution or run lifecycle scripts, and the Codex
sandbox has no network.

Add `type=semver,pattern={{major}}` to the `docker/metadata-action` tags in
`.github/workflows/publish-image.yml`. Earlier releases are already published and are not
re-tagged. From `v1.0.0` on, a tag push produces `1.0.0`, `1.0`, `1` and `latest`.

The frontend bundle does not embed the package version. The header reads the version from
`GET /api/version`, which returns `app.__version__`. A rebuild therefore produces no diff,
and the plan does not commit one. The implementer confirms this instead (Acceptance).

Rejected: a guard test that README and site docs quote the current version. It would force
a docs edit on every patch release for little value.

## Steps

1. Set `__version__ = "1.0.0"` in `app/__init__.py`.
2. Set `"version": "1.0.0"` in `frontend/package.json` (line 4).
3. In `frontend/package-lock.json`, set the top-level `"version"` (line 3) and
   `packages[""]["version"]` (line 9) to `"1.0.0"`. Touch no other line.
4. In `.github/workflows/publish-image.yml`, step `Image metadata`, make the `tags:` block:
   ```yaml
   tags: |
     type=semver,pattern={{version}}
     type=semver,pattern={{major}}.{{minor}}
     type=semver,pattern={{major}}
   ```
   Leave every `uses:` line and SHA pin unchanged.
5. In `docs/deploy.md` § Releasing, change the sentence to:
   "The image lands at `ghcr.io/nulthara/filterhelm` with tags `X.Y.Z`, `X.Y`, `X` and
   `latest`, for `amd64` and `arm64`."
6. In `README.md` (line 96), replace the sentence with:
   "Pin a version tag such as `1.0.0` instead of `latest` for anything long-lived, or use
   `1` to follow 1.x releases."

   "Pin a version tag such as `0.2.1` for anything long-lived." to
